MOTIVATION AND PROBLEM STATEMENT

We propose using Reinforcement Learning to enhance mathematical reasoning in small general-purpose language models. Current approaches to improving LLM math abilities typically rely on either massive scale (70B+ parameters) or specialized mathematical pre-training. We want to test whether PPO with dense intermediate rewards can teach math reasoning more efficiently by providing feedback on problem-solving steps rather than only final answers.

Our plan is to train Gemma-2-2B-Instruct (2B parameters) on GSM8k grade-school math problems. We're deliberately choosing a general-purpose model rather than something like Qwen2.5-Math because it gives us a clearer signal - Gemma-2-2B has around 25% baseline accuracy on GSM8k, so there's substantial room to demonstrate improvement. Our target is 20-30% absolute accuracy gain, which would bring us to 45-55% accuracy.

METHODOLOGY

We'll implement PPO using the TRL (Transformer Reinforcement Learning) library, which handles the key challenges like KL divergence penalties to prevent model collapse. The main novelty in our project is the mathematical verification environment. Rather than just checking final answers, we're designing a system that can verify intermediate reasoning steps and provide dense rewards throughout the solution process.

Here's how it works: the model receives GSM8k word problems and must output structured solutions containing Python code and explanations. We execute the code in a sandboxed environment and compare outputs to ground truth. The reward structure provides incremental feedback - the model gets small rewards for syntactically valid Python code (+0.1), successful execution (+0.2), correctly extracting numerical values (+0.3), and partial correctness (+0.5), with a larger reward for the exact correct answer (+2.0) and a penalty for wrong answers (-0.5).

We're taking a curriculum learning approach to make training more stable. In weeks 1-2, we'll train on a subset of the easiest 1,000 GSM8k problems with our basic reward structure, targeting 10-15% improvement over baseline. In weeks 3-4, we'll scale to the full GSM8k dataset with enhanced intermediate step rewards, aiming for 20-30% absolute accuracy improvement. If we're ahead of schedule, we have stretch goals to either tackle harder problems from the MATH dataset (levels 1-2) or scale up to Phi-3.5-mini (3.8B parameters).

EVALUATION AND RL PRINCIPLES

Our primary metric is accuracy on the GSM8k test set. We'll compare against three baselines: zero-shot performance (~25%), few-shot with 5 examples (~30-35%), and our RL-trained model (target: 45-55%). We'll also track secondary metrics including sample efficiency (accuracy vs training steps), intermediate step correctness rate, and training stability through policy KL divergence and reward curves.

This project emphasizes several core RL principles from the course. We're implementing policy gradient methods (PPO) for text generation, exploring reward shaping by comparing dense versus sparse rewards, using curriculum learning to progressively scale difficulty, balancing exploration and exploitation through KL penalties and entropy regularization, and improving sample efficiency by reusing experience samples across PPO epochs.

RESOURCES AND DIVISION OF LABOR

We have access to a 48GB VRAM GPU cluster with 24-hour training runs, which should be sufficient for our 2B model. Our technical stack includes Gemma-2-2B from HuggingFace, the TRL PPOTrainer, the GSM8k dataset (8,500 training problems, 1,319 test problems), and PyTorch. One team member will focus on building the verification environment, reward function, and evaluation pipeline, while the other handles PPO integration, data preprocessing, and the training loop with hyperparameter tuning.
